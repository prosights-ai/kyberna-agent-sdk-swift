# Changelog

## 0.9.0 (2026-09-21)

`ACPEngine` keeps the agent's text apart from a tool's end (2026-09-21, Kyberna console 93, release plan v0.2.14 Phase 1 step 6): GitHub Copilot CLI sends "Info: …/hello.txt" as an `agent_message_chunk` while an edit runs and "Done." as another after the `completed` update, and both landed in one text block as "hello.txtDone.". When a `tool_call` or `tool_call_update` completes or fails, text and thinking buffered so far now go out first as their own `assistant` message (no `stopReason`), the tool result follows as before with its content blocks joined by a newline, and the next chunk starts a new content block (a new `index` on the stream events), so a live view does not append it to the earlier text; the turn's `result` text joins the pieces with newlines. `FakeACPAgent` plays that shape for a prompt naming `hello.txt`. One test in `AgentACPTests/ACPEngineTests`.

## 0.8.0 (2026-09-21)

Minor bump: `ToolHosting` on `ACPEngine`, the `HostedToolServing` protocol and the `MCPServerEndpoint` type; additive over 0.7.0.

`AgentACP` gained MCP pass-through of the host's tools (2026-09-21, Kyberna release plan v0.2.14 Phase 2 step (e), console 96; validated by Kyberna's `docs/research/acp-mcp-passthrough-spike-2026-09.md` against GitHub Copilot CLI 1.0.87, which refuses the specification's mandatory stdio `McpServer` form and takes streamable HTTP). `ACPEngine` and `ResumableACPEngine` conform to `ToolHosting`: `host(_:serverName:)` before start, and the tools reach the agent through `mcpServers` on `session/new` as one MCP server named `serverName`. New in `MCPToolServer.swift`: `MCPServerEndpoint` (`http(name:url:headers:)` and `stdio(name:command:args:env:)`, `Codable`, with `wire` in the shapes the specification writes, `env` as `{"name","value"}` objects); `HostedToolNaming` (`wireName` `<serverName>_<tool>`, `policyName` `mcp__<serverName>__<tool>`, and `tool(matching:in:)`, which also reads an agent's prefixed form such as Copilot's `kyberna-kyberna_notes_search`); `MCPToolDispatch.reply(to:serverName:tools:call:)`, the JSON-RPC side of an MCP tool server (`initialize` echoing the client's `protocolVersion`, notifications unanswered, `ping`, `tools/list`, `tools/call` with a tool's failure as an `isError` result, `-32601` for anything else, which covers Copilot's `server/discover` probe); and `LoopbackMCPServer`, a streamable-HTTP server on `127.0.0.1` with an ephemeral port (Network framework), one path `/mcp`, a 64-hex-character bearer token checked on every request (401 with `WWW-Authenticate: Bearer` otherwise), JSON responses with an `Mcp-Session-Id`, `202` for notifications, `405` for `GET` (no SSE stream), `200` for `DELETE`, kept-alive connections answered in order, `Content-Length` and chunked bodies, a 4 MiB body cap, and `stop()`. At start the engine offers the loopback server as `{"type":"http",…,"headers":[Authorization]}` when the agent's `initialize` advertises `mcpCapabilities.http`, else `ACPEngineOptions.stdioToolServer` (new; a host's stdio line such as `kyb mcp-serve --session ID`) under the host's server name, else nothing and `system/hosted_tools_unavailable`; `initialized` lists the policy names in `tools` and carries `mcpTransport` (`http`, `stdio`, `none`) and `mcpHttp`. A `tool_call` or `session/request_permission` naming a hosted tool (by the request's bare title or the update's prefixed one, paired by `toolCallId`) is put to the policy and the person under the policy name, so a host's `mcp__<server>__<tool>` rows apply unchanged. New protocol `HostedToolServing: ToolHosting` in `AgentEngine` (`hostedToolList()`, `callHostedTool(_:arguments:)`), which both engines adopt: a call arriving at the server (or from a host's stdio process) runs the policy callback first, then a grant the permission flow left for that exact call (`ApprovalPayload.hash` of the policy name and arguments, so the person is asked once), else the permission handler with a `permissionRequest` on the stream, then the tool; a refusal or a throw is an `isError` result, `CancellationError` reported as `cancelled`. A refused call's `failed` update carries the engine's reason as the tool result's text (Copilot's own `rawOutput.message`, "The user rejected this tool call.", appended in parentheses), and `record(from:)` reads a `rawOutput` object's `message`. The server stops with `stop(.session)`, `stop(.kill)`, a start that fails and the child's exit. `FakeACPAgent` advertises `mcpCapabilities {http: true}` (off with `noHTTPMCP`, `FAKE_ACP_NO_HTTP_MCP`), keeps the HTTP entry of `mcpServers`, and on a prompt not naming `utils.py` plays Copilot's scenario (`server/discover`, `initialize` at `2025-11-25`, `notifications/initialized`, `GET`, `tools/list`, a `tool_call` titled `<server>-<tool>`, a `session/request_permission` titled with the bare tool name and kind `other`, `tools/call` on allow with the result as the `completed` update's content and a closing message, Copilot's `failed` update with no text on reject, `DELETE`). `clientInfo.version` is now `0.8.0`. Eight tests in `AgentACPTests/ACPToolHostingTests` (one on a raw HTTP/1.1 connection); `adoptsTheCapabilities…` now expects `ToolHosting`. No third-party package, no new `@unchecked Sendable` (Network's types are `Sendable`; the connection's back-reference is a `Mutex`-held weak box).

## 0.7.0 (2026-09-21)

Minor bump: `SwiftTool.riskOfCall` and `ToolCallRisk`; additive over 0.6.0.

`SwiftTool` gained `riskOfCall: RiskJudgment?` (2026-09-21, Kyberna release plan v0.2.13 Phase 2 step 2, the "Not done" of v0.2.12 Phase 3 step 1), `RiskJudgment` being `@Sendable ([String: JSONValue]) -> ToolCallRisk?`: a tool's own reading of one call's arguments before it runs, kept with the definition rather than in a host's table by name, after Qwen Code's `ToolInvocation.getDefaultPermission` (Apache-2.0; Kyberna's THIRD-PARTY-NOTICES.md). Both initialisers take it as a defaulted parameter after `annotations`, `SwiftTool.fixedRisk(_:)` makes a judgment that reads every call the same, and `risk(of:)` asks it; nil, from a tool without one or from a judgment that declines, means the host's own tables decide. `AgentProtocol` gained `ToolCallRisk` (`unknown`, `low`, `medium`, `high`; `String`-backed, `Codable`, `CaseIterable`), the grade a tool states; the SDK never acts on it and nothing about it goes on the wire (`SwiftTool.wire` is unchanged). No third-party package, no new `@unchecked Sendable`. Four tests in `AgentSessionTests/SwiftToolRiskTests`.

## 0.6.0 (2026-09-21)

Minor bump: the `AgentACP` target and the `fake-acp` executable; additive over 0.5.0.

New library target `AgentACP` (2026-09-21, Kyberna release plan v0.2.12 Phase 3 step 5; the research behind it is Kyberna's `docs/research/acp-engines.md`): one `AgentEngine` over the Agent Client Protocol (agentclientprotocol.com, wire `protocolVersion` 1). `ACPClient` speaks JSON-RPC 2.0 over an agent child's stdio with newline framing on `CLITransport`: `request`, or `send` (the line goes on the wire before the caller suspends, so a `session/cancel` never overtakes the prompt it cancels) and `response(for:)`, `notify`, `respond` for the agent's own requests, and `ACPError` (`remote(code:message:data:)`, `exited`, `protocolViolation`, `timeout`, `notRunning`, `unsupportedProtocolVersion`). `ACPAgentDescriptor` is one agent as a host launches it: id, display name, executable and arguments with the version pin, `ModelArgument` (`flag`, `flagEquals`, `environment`), the vendor's auth note as text, and `supportsSessionLoad`. `ACPEngine: AgentEngine, PermissionGating, ModelSwitching`: `start()` runs `initialize` (client capabilities: no `fs`, no `terminal`) then `session/new` with the working folder and an empty `mcpServers`, or `session/load` when a resume reference is set and the agent advertises `loadSession` (a refusal or a missing capability is `system/resume_unavailable` and a fresh session), and emits `initialized` (`engine: acp`, the agent's name and version from `agentInfo`, `loadSession`, `resumed`, `apiKeySource: none`); each `send` is a `session/prompt` whose `agent_message_chunk` and `agent_thought_chunk` updates become one `assistant` message (with `streamEvent` text and thinking deltas when partial messages are on), `tool_call` a `toolUse` block, `tool_call_update` with `completed` or `failed` a `user` message with the `toolResult` (content blocks, diffs and terminals rendered as text), `plan` a `system/plan` row and any other update `system/acp_<kind>`; the prompt's `stopReason` ends the turn as a `ResultMessage` (`end_turn` success, `max_turn_requests` `error_max_turns`, `cancelled` in the CLI's interrupt shape so `wasInterrupted` holds, a JSON-RPC error `error_during_execution` with the error text); a tool call the agent never closed gets an error result so every use is paired. `session/request_permission` goes through the policy first and the person second: `allow_once` for an allow, `allow_always` when the handler asks to remember (`updatedPermissions`) and the agent offers it, `reject_once` (else `reject_always`) for a denial with `permissionDenied` on the stream, and `cancelled` for every open request when the turn is cancelled, as the protocol requires; other agent requests (`fs/*`, `terminal/*`) are answered method-not-found. `steer` queues the text as the next prompt (`steeringQueued`), `steerNow` cancels first; `stop(.turn)` is `session/cancel` with the turn ended by the engine after `cancelGrace` if the agent does not; `.session` closes stdin then SIGTERM then SIGKILL after `exitGrace` each; `pause`/`resume` are SIGSTOP/SIGCONT. `setModel` after start records `system/model_restart` and ends the child, since the model is a launch argument; the host carries the conversation and starts the engine again. `ACPEngine.make(options:)` returns `ResumableACPEngine` (the engine with `Resumable` in front, a wrapper because a `Sendable` class is final) for a descriptor with `supportsSessionLoad`. Absent by design: `ToolHosting` (ACP's `mcpServers` pass-through is a later step), `HookCapable`, `ContextReporting`, `FileRewinding`, `EffortSetting`, `ReasoningControl`, `ImageAttaching`, `RateLimitReporting`. `AgentTestKit` gained `FakeACPAgent` and `FakeACPMain`, and the package the `fake-acp` executable: a scripted agent with one prompt scenario (thought, message, `tool_call`, `session/request_permission`, the tool's end, `end_turn`), `fail` and `sleep` prompts, `--model` echoed as `currentModelId`, `FAKE_ACP_LOAD_SESSION` and `FAKE_ACP_EXIT_ON_PROMPT`. 13 tests in `AgentACPTests`. `AgentACP` depends on `AgentProtocol`, `AgentTransport`, `AgentSession` (for `PolicyCallback`, `StopSeverity` and the other types the engine protocols are written in) and `AgentEngine`; no third-party package, no new `@unchecked Sendable`.

## 0.5.0 (2026-09-21)

Minor bump: `DirectEngineOptions.compaction` changes type from `(any CompactionStrategy)?` (default `SummarizingCompaction()`) to `CompactionOptions?` (default nil, no compaction); everything else is additive over 0.4.0.

`AgentDirect` gained compaction for the engines that have none of their own (2026-09-21, Kyberna release plan v0.2.12 Phase 3 step 3; `Compaction.swift`, adapted from Pi, OpenHands and OpenCode under MIT, see Kyberna's THIRD-PARTY-NOTICES.md). `CompactionOptions`: `triggerTokens` (nil: 70 percent of `contextWindowTokens`), `keepFirst` (2), `keepRecentTokens` (nil: 25 percent of the window), `minimumProgress` (0.1) with `maxProgressRetries` (5, the kept tail scaled by 0.8 per retry), `summaryModel` (nil: the conversation's model, same provider), `summaryMaxTokens` (2,000), `maxToolResultChars` (20,000), `spillHeadChars` (2,000), `spillDirectory` (nil: `.kyberna/tool-output/` under the working directory), and the fixed `summaryPrompt`. Before a model call, when the history's estimated tokens (the provider's last usage, else four characters per token) pass the trigger, the engine cuts at the newest user message without tool results that keeps the recent budget (never inside a tool call and result pair; the head moves past a pair it would split), summarises the middle with one call, replaces it with one assistant message beginning `[compacted: N messages]`, records `ConversationHistory.keptBoundary`, and emits `Message.system(subtype: "compaction", data: [messages, tokensBefore, tokensAfter, keptBoundary])`; a repeated pass summarises from the previous boundary, so the earlier summary and what it kept fold into the next one. A failed summary call leaves the history and emits `system/compaction_failed` once until a pass succeeds. Tool output over `maxToolResultChars` is written to `<spillDirectory>/<toolUseId>.txt` and the recorded result keeps the first `spillHeadChars` plus a line naming the file and its size; a failed write leaves the result as it was. `CompactionStrategy` and `SummarizingCompaction` are deprecated and no longer called. Eleven tests in `AgentDirectTests/CompactionTests`.

## 0.3.0 (2026-09-20)

Minor bump: the `AgentDirect` target (direct API engine) and `FakeModelProvider` in `AgentTestKit`; additive over 0.2.0.

New library target `AgentDirect` (2026-09-20, release plan v0.2.0 Phase 2 step 2; plan Phase 8, ADR 0015): the direct API engine. `ModelProvider` is the provider contract (one `ModelRequest` in, an always-streaming `AsyncThrowingStream<ModelEvent, Error>` out; the eight contract points are in the doc comment at the top of `ModelProvider.swift`), with `ModelRequest`, `ModelMessage`, `ModelContentBlock`, `ModelToolDefinition`, `ModelThinking`, `ModelEvent`, `ModelStopReason`, `ModelStopDetails`, `ModelUsage` and `ProviderError` (two renderings: `description` and `feedbackMessage`). `AnthropicProvider` maps to the Messages API: SSE over `URLSession.bytes(for:)` split at newlines, `SSEParser`, `StallWatchdog`, `RetryingHTTPClient` with `RetryPolicy` (three attempts, full jitter, `Retry-After`, on 408/429/500/502/503/504 and connection failures; retry lives in transport, never in the loop), `cache_control` on the last tool and the last system block, `output_config.effort` and `output_config.format` for structured output, `stop_details` on a refusal; the key is a `Secret` read once in `buildRequest`. `ToolExecutor` runs waves (consecutive read-only tools concurrently, everything else serially) and returns results in call order, bounds every handler by `toolTimeout` (30 s), caps result text, and takes a `ToolGate` so a host's policy engine answers allow/ask/deny/defer before a tool runs; `ProcessRegistry` and `ToolContext.run` spawn children with `posix_spawn` into their own process groups, cap output at 64 KiB per stream, and end them with SIGTERM then SIGKILL. `ConversationHistory` is the engine's message log (safe cuts, `repairInterrupted`), with `CompactionStrategy` and a `SummarizingCompaction` default. `DirectAPIEngine: AgentEngine` adopts `ModelSwitching`, `EffortSetting`, `ReasoningControl`, `PermissionGating`, `ToolHosting` (tools appear as `mcp__<server>__<tool>`), `ImageAttaching` and `ContextReporting`, and omits `Resumable`, `HookCapable`, `FileRewinding` and `RateLimitReporting`; it emits the same `Message` stream as the Claude Code engine (`initialized` with `apiKeySource: "direct"`, `assistant`, `user` tool results, `streamEvent` in the Messages API shape when partial messages are on, `result`, `exited`). Interrupt: the model stream is cancelled and its partial output discarded, the wave is cancelled and awaited, registered process groups are ended, every unanswered `tool_use` gets an `is_error` result "Interrupted by user", and the `ResultMessage` has subtype `error_during_execution` with `wasInterrupted == true`. Also: `max_tokens` continuation (three recoveries), loop detection (feedback on the third identical call, turn ends on the fifth), queued steering delivered with the next request, a built-in `AskUserQuestion` tool when a question handler is set. `AgentTestKit` gained `FakeModelProvider` (scripted `ModelEvent` streams) and `FakeStreamingHTTPClient` (scripted HTTP responses, raw SSE bytes through the real parser) and now depends on `AgentDirect`. 35 tests in `AgentDirectTests`; the live Anthropic test runs only with `KYBERNA_LIVE=1` and `ANTHROPIC_API_KEY`, tagged `requiresNetwork`. `Scripts/sdk-api-check.sh`: additions only.

## 0.2.0 (2026-09-19)

Minor bump: `AgentEngine` capability protocols, named keys on `Message` and `ContentBlock`, `Message.taskNotification` gains `reason`. Recorded and tested against Claude Code 2.1.270 through 2.1.273 and 2.1.278.

`Message` and `ContentBlock` encode with every field named (2026-09-19, gateway backlog 9): the four single-value `Message` cases write `message`, `payload` and `result` keys and the two single-value `ContentBlock` cases write `text` and `thinking`, where the synthesizer wrote `_0`; both decoders still accept `_0` for rows and parts written by 0.1.x. `Message.taskNotification` gained `reason: TaskNotificationReason?` (the one intended API break in 0.2.0; a four-element pattern is needed to bind it). `SessionOptions` gained `permissionPrompts` (`--permission-prompts host|none`), `systemPromptSnapshot` (`--system-prompt-snapshot on|off`), `mcpStartupWaitMs` and `emitStartupTiming` (the two startup environment variables); `ClaudeSession` decodes result frames through `ResultMessage(wire:)`. `AgentProtocol` gained the 2.1.278 and TypeScript-SDK fields: `MCPServerRef`, `SystemInit` with `scratchpad_path` and `startup_timing`, `StartupFailureReason` and the latency fields on `ResultMessage`, `UsageReport`, `SlashCommand.builtin`, `UserMessage.pastedContent`, `TaskNotificationReason`; every recorded fixture line from 2.1.270 to 2.1.278 decodes.

`AgentEngine` gained `engineVersion` (default nil) and eleven optional capability protocols, each with a documented fallback: `ModelSwitching`, `EffortSetting`, `ReasoningControl`, `Resumable`, `PermissionGating`, `HookCapable`, `ToolHosting`, `ImageAttaching`, `ContextReporting`, `FileRewinding`, and `RateLimitReporting` (2026-09-19). `ClaudeCodeEngine` adopts all of them, exposes `options` and a static `childEnvironment(options:)`, and moved to its own file. `ClaudeSession.options` is now `private(set) var`, with `configure(_:)` and `isStarted` added to edit it before start; `ClaudeSession` emits `system/version_warning` on the stream when the version check produces a warning. `EngineError`, `ReasoningDisplay`, and `ImageAttachment` are new public types. `AgentEngineTests` now depends on `AgentTestKit`. `Scripts/sdk-api-check.sh` against `sdk-swift/v0.1.0` reports no breaking change in any target: `ClaudeSession.options` moving from `let` to `private(set) var` is source-compatible for readers, and `engineVersion` is defaulted, so existing `AgentEngine` conformers still compile.

Renamed the package and module from `ClaudeAgentKit` to `KybernaAgentKit` (2026-09-17), following the convention Anthropic uses for its own Agent SDKs (the vendor's product in the name, the engine in the type names) and its branding guidance that a partner product keeps its own branding. Type names are unchanged: `ClaudeSession` and `ClaudeCodeEngine` still name the Claude Code engine. The API baseline tag stays `sdk-swift/v0.1.0`; `Scripts/sdk-api-check.sh` reads the old folder name from that tag.
